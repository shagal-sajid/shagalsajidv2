Hosting Architecture & CMS Options

Hostinger Shared Hosting runs PHP and serves static directories exceptionally fast. Since you want to publish **blog posts** and **projects** dynamically, how should we handle the Content Management System (CMS)?

We evaluate the 3 best CMS options tailored for Hostinger:

Option A: Free Headless CMS (Sanity / Strapi)

Write your blogs in a beautiful, secure online dashboard hosted for free on Sanity.io. Your static website fetches the posts dynamically using simple browser-based fetch() requests.

Pros: 100% static hosting on Hostinger (unmatched speed), secure, visual dashboard.

Option B: Flat-File JSON/Markdown

Zero databases or outer APIs. Blog posts are stored as markdown files or inside a local list configuration (posts.json). We render them directly via vanilla JS.

Pros: 100% under your control, no third-party downtime, runs forever without updates.

Option C: Flat-File PHP CMS (Kirby / Grav)

Since Hostinger supports PHP, you can run Grav or Kirby. They don't use slow SQL databases; instead, they serve flat files and provide a dashboard directly at shagalsajid.com/admin.

Pros: Admin panel runs directly on Hostinger, highly flexible.

Automated GitHub Actions FTP Deployment Pipeline

Every time you edit your local code or JSON files and push to GitHub, a runner compiles the site and deploys it automatically to Hostinger via SFTP: 

name: Deploy Website
on:
  push:
    branches:
      - main
jobs:
  web-deploy:
    name: Build and Deploy
    runs-on: ubuntu-latest
    steps:
    - name: Get latest code
      uses: actions/checkout@v4

    - name: Set up Node.js (For local build compile step)
      uses: actions/setup-node@v4
      with:
        node-version: 20
        cache: 'npm'

    - name: Install dependencies & Build
      run: |
        npm install
        npm run build

    - name: FTP Deploy to Hostinger
      uses: SamKirkland/FTP-Deploy-Action@v4.3.5
      with:
        server: ${{ secrets.FTP_SERVER }}
        username: ${{ secrets.FTP_USERNAME }}
        password: ${{ secrets.FTP_PASSWORD }}
        local-dir: ./dist/ # Output directory folder
        server-dir: /public_html/
